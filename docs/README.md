# OctoAcme Project Management Docs

This folder contains OctoAcme's lightweight project management guidance for cross-functional delivery work. The process is built around customer-first outcomes, iterative delivery, clear ownership, data-informed decisions, and continuous learning. Teams use these documents to move consistently from project initiation through planning, execution, release, and retrospective improvement without adding unnecessary process overhead.

At a high level, OctoAcme starts by defining the problem, goals, stakeholders, success metrics, timeline, and initial risks. Once work is approved, the team turns that direction into a prioritized backlog, a release plan, clear acceptance criteria, and a Definition of Done. During execution, delivery is tracked through regular team cadences, project boards, pull request reviews, CI checks, QA activities, and weekly risk/status reviews.

The same documentation set also clarifies how Project Managers, Product Managers, developers, QA/testing, and stakeholders work together. Communication is structured around a shared source of truth, recurring updates, and clear escalation paths, while release guidance emphasizes readiness checks, smoke tests, rollback planning, and post-release verification. Retrospectives then turn lessons learned into specific improvement actions for future work.

## Core principles

- **Customer-first**: prioritize customer value and usability.
- **Iterative delivery**: deliver small, testable increments.
- **Clear ownership**: keep PM, Product, engineering, QA, and stakeholder responsibilities visible.
- **Data-informed decisions**: use success metrics, delivery signals, and release verification to guide decisions.
- **Continuous learning**: use feedback, retrospectives, and psychological safety to improve over time.

## Core workflow at a glance

1. **Initiation**: confirm the business need, goals, stakeholders, success metrics, timeline, and initial risks.
2. **Planning**: break work into shippable increments, prioritize the backlog, define acceptance criteria, identify dependencies, and map milestones.
3. **Execution & tracking**: deliver in small increments using the project board, PR reviews, CI, QA, demos, and regular status/risk reviews.
4. **Release & deployment**: confirm readiness, complete release notes and rollback planning, deploy safely, and verify outcomes.
5. **Retrospective & improvement**: capture what worked, what did not, and which action items should be fed back into the backlog.
